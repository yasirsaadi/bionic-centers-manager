# 4.bq — عنوانُ جهاز الموظّف الحقيقيّ في سجلّ التدقيق (٢٠٢٦-١٠-٠٣)

## المشكلة
`audit_log.ip_address` (نحو ٩٠ موضعَ كتابة) يحفظ `req.ip`، وكان **عنوانَ حافّة Cloudflare** لا جهازَ الموظّف — فلا يقول
تحقيقٌ (كفروع أيوب وعناد، §4.ap) من أيّ جهازٍ جاء الفعل. والموظّفون كلُّهم والمالكُ يدخلون **من رابط Render المباشر**.

## القياس قبل الإصلاح (لا تخمين)
نقطةُ فحصٍ مؤقّتة للمسؤول العام (#494، أُزيلت هنا) فتحها المالكُ من الرابط المباشر، وقارنها بـ`ifconfig.me`:
```
reqIp           172.69.150.58                       ← حافّةُ Cloudflare (ما كان يُحفظ)
socket          10.27.139.140                       ← موازنُ Render الداخليّ
x-forwarded-for 37.239.130.199, 172.69.150.58       ← الجهاز، ثمّ الحافّة
cf-connecting-ip / true-client-ip  37.239.130.199   ← = ifconfig.me
cf-ray          …-FRA
```
فـ**Cloudflare هي حافّةُ Render نفسِها** — الرابطُ المباشر يمرّ بها أيضاً. وكان `trust proxy = 1` يقف عند الحافّة.

## الإصلاح — موضعٌ واحد يصحّح المواضعَ كلَّها
`server/net/trust_proxy.ts`: `TRUST_PROXY` = الشبكاتُ الخاصّة + نطاقاتُ Cloudflare المنشورة (مطابقةٌ حرفياً لـ
`cloudflare.com/ips-v4` و`ips-v6` يوم الإصلاح)، ويضبطه `setupAuth` بدل `1`. فـExpress يتخطّى من اليمين ما نثق به ويقف عند
أوّل غريب — الجهاز. **والمزوَّرُ** في ترويسة الطالب يقع يسارَ عنوانه الحقيقيّ فلا يُبلَغ. ولم يُلمَس أيٌّ من مواضع الكتابة.

**إن أضافت Cloudflare نطاقاً** لم يُذكر ظهر عنوانُ حافّتها بدل الجهاز — خطأٌ ظاهر لا مزوَّر — فيُضاف سطرُه.
**والماضي لا يُصحَّح**: الصفوفُ القديمة تبقى بعنوان الحافّة.

## التحقّق
`npm run test:trust-proxy` — خادمُ Express حقيقيّ: الشكلُ المقيس ⟵ الجهاز؛ المزوَّر لا يُبلَغ؛ حافّةُ IPv6؛ قفزةٌ غريبة يقف
عندها؛ و`setupAuth` يضبط القيمة. والعكسُ بـ`trust proxy = 1` يُسقط ١ و٢ و٣ و٦ وحدها.
